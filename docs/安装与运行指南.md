# 安装与运行指南（macOS · 小白版）

这份文档面向「第一次接触 Flutter」的同学：从一台干净的 Mac 开始，把这个项目跑起来。
每一步都写了 **怎么做**、**成功的样子**、**失败的样子和怎么办**。

首次完整装完大约需要 **1.5 ~ 3 小时**（大部分时间在下载），第二次以后只需要第 8 ~ 10 步，几分钟就能跑起来。

---

## 开始之前，先确认三件事

| 项目 | 要求 | 怎么确认 |
| --- | --- | --- |
| 电脑 | macOS（Apple 芯片 / Intel 都可以） | 左上角  → 关于本机 |
| 磁盘空间 | 至少空出 **30 GB**（Flutter + Xcode + Android 都很占地方） |  → 关于本机 → 储存空间 |
| 网络 | 能下载大文件；国内建议按第 1 步配置镜像 | 随便打开一个网页试试 |

还要先想清楚一件事：**你想把 App 跑到哪里？**

| 目标 | 额外需要 |
| --- | --- |
| 只想先看到界面 | 装完第 1、2 步就够了，可以直接跑 macOS 桌面版或 Chrome |
| Android 手机 / 模拟器 | 还要第 4、5 步（Android Studio + SDK） |
| iPhone / iPhone 模拟器 | 还要第 3 步（Xcode，只能在 Mac 上） |

---

## 第 1 步：安装 Flutter SDK

**怎么做**

1. 打开官网下载页：<https://docs.flutter.dev/get-started/install/macos>
2. 下载 **stable** 版本的压缩包，Apple 芯片选 `flutter_macos_arm64_xxx-stable.zip`，Intel 选 `flutter_macos_x64_xxx-stable.zip`
3. 解压到一个**路径里没有中文和空格**的固定目录，推荐 `~/work`：

```bash
mkdir -p ~/work
unzip ~/Downloads/flutter_macos_arm64_*-stable.zip -d ~/work
```

装完的目录结构应该是 `~/work/flutter/bin/flutter`。

> 也可以用 Git 安装：`git clone -b stable --depth 1 https://github.com/flutter/flutter.git ~/work/flutter`

**✅ 成功的样子**

- `~/work/flutter` 文件夹里能看到 `bin`、`packages`、`examples` 等目录
- 这时还**不能**直接在终端敲 `flutter`，因为还没配环境变量（见第 2 步）

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 解压报错、文件夹下多了一层嵌套 | 解压方式不对 | 确认最终路径是 `~/work/flutter/bin/flutter`；如果变成了 `~/work/flutter/flutter/...`，把里层文件夹整体移到 `~/work/flutter` |
| 下载到一半卡住 / 断流 | 网络问题 | 换网络，或用国内镜像下载：<https://flutter.cn> |
| 提示「无法打开，因为来自身份不明的开发者」 | macOS 安全限制 | 右键点压缩包 → 打开；仍不行就在「系统设置 → 隐私与安全性」里允许 |

## 第 2 步：把 Flutter 加进终端环境

**怎么做**

1. 用文本编辑器打开配置文件（Mac 默认是 `~/.zshrc`）：

```bash
open -e ~/.zshrc
```

2. 在文件末尾追加下面几行，然后保存：

```bash
export FLUTTER_HOME=$HOME/work/flutter
export DART_HOME=$FLUTTER_HOME/bin/cache/dart-sdk
export PATH=$FLUTTER_HOME/bin:$PATH

# 国内下载镜像（不加这一步，pub get 和 SDK 下载会非常慢甚至超时）
export PUB_HOSTED_URL=https://pub.flutter-io.cn
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

3. **关掉终端窗口重新打开**（或执行 `source ~/.zshrc`），然后验证：

```bash
flutter --version
```

**✅ 成功的样子**

终端打印出版本信息，例如：

```text
Flutter 3.47.0 • channel stable
Framework revision ... • Dart 3.13.0
```

（第一次执行会先自动下载 Dart SDK，可能要等 1 ~ 5 分钟，属于正常现象。）

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `zsh: command not found: flutter` | PATH 没生效 / 路径写错 | 重新打开终端；检查 `~/work/flutter/bin/flutter` 是否真实存在；`echo $PATH` 看有没有包含它 |
| 提示 `Operation not permitted` 或权限错误 | Flutter 目录被系统保护（Desktop、Documents 等目录会被保护） | 把 Flutter 放到 `~/work` 这类不受保护的位置，不要放在桌面 |
| 一直卡在下载、速度极慢 | 没配镜像 | 确认 `PUB_HOSTED_URL`、`FLUTTER_STORAGE_BASE_URL` 两行已写入并重新打开过终端 |

## 第 3 步：安装 Xcode（只有要跑 iPhone / iPad 才需要）

**怎么做**

1. 打开 App Store，搜索 **Xcode**，安装（约 10 ~ 20 GB，很慢，可以先去吃饭）
2. 装完第一次必须让它完成初始化，终端执行：

```bash
sudo xcodebuild -runFirstLaunch
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
xcodebuild -version
```

3. 安装 CocoaPods（iOS 的第三方依赖管理）：

```bash
sudo gem install cocoapods
pod --version
```

> 如果 `sudo gem install` 报错，可以先装 Homebrew，再执行 `brew install cocoapods`。

**✅ 成功的样子**

- `xcodebuild -version` 打印出 `Xcode 26.6` 之类的版本号
- `pod --version` 打印出例如 `1.16.2`

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `xcode-select: error: tool 'xcodebuild' requires Xcode` | 只装了命令行工具，没装完整 Xcode | 到 App Store 装完整 Xcode，再执行 `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer` |
| 提示需要同意许可协议 | 首次使用 | `sudo xcodebuild -license accept` |
| `pod: command not found` | CocoaPods 没装 | 重新执行 `sudo gem install cocoapods` |
| 跑 iOS 时提示 `CocoaPods not installed` | 同上 | 装完 CocoaPods 后回到项目目录重新 `flutter run` |

## 第 4 步：安装 Android Studio 和 Android SDK（只有要跑 Android 才需要）

**怎么做**

1. 下载并安装 Android Studio：<https://developer.android.google.cn/studio>
2. 第一次打开会进入安装向导，一路下一步，让它自动装好 **Android SDK**（默认位置 `~/Library/Android/sdk`）
3. 在 Android Studio 里打开 **Settings → Languages & Frameworks → Android SDK**，确认勾选并安装：
   - `Android SDK Platform`（本机用的是 Android 36 / API 36）
   - `Android SDK Build-Tools`（36.0.0）
   - `Android SDK Command-line Tools (latest)`
   - `Android SDK Platform-Tools`
4. 还需要 **JDK 17**（本机用的是 `/Library/Java/JavaVirtualMachines/jdk-17.jdk`）
5. 在 `~/.zshrc` 里补上 Android 路径，然后重新打开终端：

```bash
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH
```

6. 告诉 Flutter 这两个路径在哪：

```bash
flutter config --android-sdk $ANDROID_HOME
flutter config --jdk-dir=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home
```

**✅ 成功的样子**

- 终端执行 `adb version` 能打印版本号
- 终端执行 `sdkmanager --list` 能列出可安装的组件
- `flutter doctor -v` 的 Android 一行显示 SDK 路径和版本号（如 `Android SDK version 36.0.0`）

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `adb: command not found` | PATH 没配或 SDK 没装全 | 检查 `~/Library/Android/sdk/platform-tools/adb` 是否存在；重开终端 |
| `Unable to locate Android SDK` | Flutter 不知道 SDK 在哪 | 执行 `flutter config --android-sdk $ANDROID_HOME` |
| 提示 Java 版本不对 / `Unsupported class file major version` | JDK 版本不是 17 | 装 JDK 17 后执行 `flutter config --jdk-dir=<JDK17 路径>` |
| 下载 SDK 组件很慢 | 网络问题 | Android Studio 里设置代理，或换网络重试 |

## 第 5 步：接受 Android 许可协议

这一步很关键：**没做这一步，Android 就永远跑不起来**，而且报错信息看起来和许可毫无关系。

**怎么做**

```bash
flutter doctor --android-licenses
```

一路输入 `y` 回车（会问好几次，全部同意）。

**✅ 成功的样子**

- 最后提示 `All SDK package licenses accepted.`
- 再执行 `flutter doctor`，Android 一行从 `!` 变成 `✓`

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Android license status unknown` | 没装 `cmdline-tools` | 回第 4 步，用 Android Studio 的 SDK Manager 装上 `Android SDK Command-line Tools (latest)`，再重跑本步骤 |
| `sdkmanager: command not found` | PATH 里没有 cmdline-tools | 确认 `~/Library/Android/sdk/cmdline-tools/latest/bin` 已加入 PATH 并重开终端 |
| 提示需要 Java | 缺 JDK | 回第 4 步装 JDK 17 |

> 当前这台电脑的现状：Android 许可**还没接受**，是 `flutter doctor` 里唯一的黄色警告，执行一次本步骤即可解决。

## 第 6 步：整体体检（flutter doctor）

**怎么做**

```bash
flutter doctor -v
```

**✅ 成功的样子**

用到的部分都是 `✓`，例如：

```text
[✓] Flutter (Channel stable, 3.47.0 ...)
[✓] Android toolchain - develop for Android devices (Android SDK version 36.0.0)
[✓] Xcode - develop for iOS and macOS (Xcode 26.6)
[✓] Chrome - develop for the web
[✓] Connected device (4 available)
```

**❌ 失败的样子和怎么办**

- `[!]` 是警告，`[✗]` 是错误。**只要还有 `[✗]`，先别往下走**，按前面几步补。
- 只有 `[!] Android licenses` → 回第 5 步。
- 只有 `[!] Connected device` 里的无线设备报错（例如搜索「某某的 iPhone」失败）→ **可以忽略**，用数据线连接或改用模拟器即可。
- 提示 `Network resources` 不可用 → 网络或镜像没配好，回第 2 步。

## 第 7 步：把项目放到电脑上

**怎么做**

二选一：

```bash
# 方式 A：从 Git 仓库克隆
git clone <项目仓库地址> ~/Desktop/Demo
cd ~/Desktop/Demo
```

```bash
# 方式 B：从同事那里拷贝整个项目文件夹
# 直接拖到桌面，然后 cd 进去
cd ~/Desktop/Demo
```

**✅ 成功的样子**

项目根目录下能看到这些关键内容：

```text
pubspec.yaml      # 依赖清单，必须有
lib/              # 全部源码，必须有
assets/           # 图片资源
test/             # 测试
android/ ios/ macos/ web/ windows/ linux/
```

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 找不到 `pubspec.yaml` | 当前目录不对（进到了子目录或上一级） | `pwd` 看当前路径，`ls` 看有没有 `pubspec.yaml` |
| 只有 `lib` 没有 `android`/`ios` | 只拷了部分文件 | 重新完整拷贝；平台目录缺失可以用 `flutter create .` 补回来 |

## 第 8 步：安装项目依赖（flutter pub get）

**怎么做**

```bash
cd ~/Desktop/Demo
flutter pub get
```

**✅ 成功的样子**

结尾出现 `Got dependencies!` 或 `Changed N dependencies!`，并且项目下生成了 `.dart_tool/` 目录和 `pubspec.lock` 文件。

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 卡住不动 / 连接超时 | 没配国内镜像或网络不通 | 回第 2 步确认 `PUB_HOSTED_URL` 已配置，重开终端再试 |
| `Because xxx requires SDK version ^3.13.0, version solving failed` | Flutter 版本太旧 | 执行 `flutter upgrade`，本项目需要 Flutter 3.47 / Dart 3.13 左右 |
| `The current Dart SDK version is ...` | 同上 | 同上 |
| 提示找不到 `flutter_riverpod` 等包 | 网络或缓存问题 | 执行 `flutter pub cache repair` 后重试 |

## 第 9 步：准备一台「设备」

**怎么做**（任选一种）

```bash
flutter devices          # 先看看有哪些可用设备
```

| 想跑在哪 | 操作 |
| --- | --- |
| Android 手机 | 手机上打开「开发者选项 → USB 调试」，用数据线连接电脑，手机上弹窗点「允许」 |
| Android 模拟器 | Android Studio → Device Manager → 新建/启动一个模拟器 |
| iPhone 手机 | 用数据线连接，手机上点「信任此电脑」 |
| iPhone 模拟器 | 终端执行 `open -a Simulator` |
| macOS 桌面版 | 什么都不用做 |
| Chrome 浏览器 | 什么都不用做 |

**✅ 成功的样子**

`flutter devices` 列出的设备里有你想要的，例如：

```text
PLA110 (mobile)  • 3B6F6GE61QHYFHW7 • android-arm64 • Android 15 (API 35)
中文iPhone17 (mobile) • 142B9E11-...  • ios • iOS 26.5 (simulator)
macOS (desktop)  • macos • darwin-arm64
Chrome (web)     • chrome • web-javascript
```

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Android 手机不出现 | 没开 USB 调试 / 数据线只能充电 | 换一根数据线；手机上重新授权；终端执行 `adb devices` 看有没有设备 |
| 模拟器启动后仍不出现 | 模拟器还没启动完成 | 等模拟器完全进入桌面，再执行一次 `flutter devices` |
| iPhone 真机不出现 | 没信任电脑 / 没开开发者模式 | 手机上「设置 → 隐私与安全性 → 开发者模式」打开并重启；重新插线点「信任」 |
| 提示无线设备连接失败 | 无线调试条件不满足 | 换成数据线连接，或忽略这个警告 |

## 第 10 步：运行项目（flutter run）

**怎么做**

```bash
cd ~/Desktop/Demo
flutter run                       # 有多个设备时会让你选一个
flutter run -d chrome             # 指定跑在浏览器
flutter run -d macos              # 指定跑在 macOS 桌面
```

首次运行要编译，Android / iOS 还要下载 Gradle 与 CocoaPods 依赖，**等 2 ~ 10 分钟是正常的**。

**✅ 成功的样子**

- 终端出现 `Flutter run key commands.` 这一段提示（说明已连上调试）
- 设备上先看到**启动页**，大约 1 秒后自动进入**带四个底部 Tab 的主界面**：首页 / 设备 / 活动 / 我的
- 首页能看到「基础框架测试页」、屏幕尺寸信息、「保存名称」输入框

常用按键（终端里按）：

| 按键 | 作用 |
| --- | --- |
| `r` | 热重载（改完代码刷新界面，最常用） |
| `R` | 热重启（状态也重置） |
| `q` | 退出 |

**❌ 失败的样子和怎么办**

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `No supported devices found` | 没有可用设备 | 回第 9 步 |
| `CocoaPods not installed`（iOS） | 缺 CocoaPods | 回第 3 步 |
| `Android license status unknown` | 没接受许可 | 回第 5 步 |
| `Gradle task assembleDebug failed` | 首次下载依赖失败 / 缓存坏了 | 等首次下载完成再试；仍失败执行 `cd android && ./gradlew --stop && cd ..`，或删除 `~/.gradle/caches` 后重试 |
| 界面白屏 / 红屏报错 | 代码或资源问题 | 看终端最上面的第一段红色错误，通常写明了文件和行号 |
| 界面跑起来但「网络测试页」请求失败 | **正常现象**：项目里的服务地址是占位域名 | 见文末「本项目专属说明」 |

## 第 11 步：三项自检（确认环境真的没问题）

**怎么做**

```bash
cd ~/Desktop/Demo
flutter test              # 跑单元测试 + 界面测试
flutter analyze           # 静态检查
flutter build apk --debug # 构建一个 Android 调试包
```

**✅ 成功的样子**

| 命令 | 成功输出 |
| --- | --- |
| `flutter test` | `All tests passed!`（本项目共 9 个测试） |
| `flutter analyze` | `No issues found!` 或只有 `info` 级别的提示，**error 和 warning 必须是 0** |
| `flutter build apk --debug` | `✓ Built build/app/outputs/flutter-apk/app-debug.apk` |

**❌ 失败的样子和怎么办**

| 现象 | 处理 |
| --- | --- |
| `flutter test` 有失败用例 | 看是哪一条，通常是环境问题；先确认 `flutter pub get` 已成功 |
| `flutter analyze` 出现 `error •` | 说明代码有真问题，把整行贴出来给人看 |
| `flutter analyze` 只有 `info •` | 可以忽略（本项目有 27 条既有命名/样式提示，与参考框架一致） |
| `flutter build apk --debug` 失败且提 licenses | 回第 5 步 |

## 第 12 步（可选）：跑到自己的 iPhone 上

1. `open ios/Runner.xcworkspace` 用 Xcode 打开工程
2. 左侧选中 `Runner` → `Signing & Capabilities` → **Team** 选你自己的 Apple ID
3. 把 **Bundle Identifier** 改成全世界唯一的值（例如 `com.你的名字.demo`），原来的 `com.isurpass...` 会冲突
4. 手机连上电脑，Xcode 顶部选你的手机 → 点 ▶️ 运行
5. 手机上首次会提示「不受信任的开发者」：设置 → 通用 → VPN与设备管理 → 信任该证书

**✅ 成功的样子**：App 图标出现在手机桌面，点击后进入主界面。
**❌ 失败的样子**：`Signing for "Runner" requires a development team` → 第 2 步没选 Team；`No profiles for ... were found` → 第 3 步 Bundle Identifier 没改成唯一的。

## 常见问题速查表

| 现象 | 大概率原因 | 一句话处理 |
| --- | --- | --- |
| `command not found: flutter` | PATH 没配 | 回第 2 步，重开终端 |
| 下载依赖极慢 / 超时 | 没配国内镜像 | 回第 2 步 |
| Android 跑不起来，报错看不懂 | 许可没接受 | 回第 5 步 |
| iOS 跑不起来，提示 CocoaPods | 没装 CocoaPods | 回第 3 步 |
| 手机上没这个 App | 设备没连上 | 回第 9 步 |
| 报「找不到设备」 | 同上 | `flutter devices` 看列表 |
| 改了代码界面没变 | 没热重载 | 终端里按 `r` |
| 界面白屏 | 编译失败或资源缺失 | 看终端报错的**第一段**红色文字 |
| 想从头再来一遍 | 缓存脏了 | `flutter clean && flutter pub get` |

## 本项目专属说明（新人必读）

1. **技术栈**：Flutter + Riverpod（状态/依赖注入）+ GoRouter（路由）+ Dio（网络）+ SharedPreferences（本地存储）。
   不要引入 GetX，也不要用静态服务定位器，规范见 `.codex/skills/flutter_riverpod_foundation/SKILL.md`。
2. **启动流程**：`lib/main.dart` → `AppBootstrap.initialize()`（初始化本地存储与网络环境）→ `ProviderScope` → `MaterialApp.router`。
3. **界面骨架**：`/` 是启动页，约 0.9 秒后进入 `/home`、`/devices`、`/activity`、`/profile` 四个底部 Tab。
4. **网络测试页请求失败是正常的**：`lib/core/network/network_config.dart` 里各环境 `baseUrl` 都是占位域名 `https://demo.com`，
   仓库里不保存真实服务地址。联调时把它换成真实地址，或用 `flutter run --dart-define=APP_ENV=production` 切换环境。
5. **应用标识**：`com.isurpass.flutter.riverpod.foundation`，显示名 `flutter_riverpod_foundation`（iOS 为 `Keemple Foundation`）。
   要发布到自己的账号下，记得改成自己的包名。
